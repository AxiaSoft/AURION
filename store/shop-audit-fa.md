# گزارش عیوب سخت‌گیرانه — سایت فروشگاه AURION Keys

تاریخ: 2026-08-26
دامنه بررسی: `store/keyserver/` (فروشگاه صدور کلید) + ارتباط با `apps/web` و `backend`

## 1. باگ گزارش‌شده: پشتیبانی کار نمی‌کند
- **شرح**: کاربر روی تب پشتیبانی کلیک می‌کند، هیچ اتفاقی نمی‌افتد.
- **ریشه‌های احتمالی**:
  - `render()` async است اما `go()` آن را await نمی‌کند؛ در صورت خطای fetch، صفحه نیمه‌کاره می‌ماند.
  - `contactCard()` اگر `SUPPORT_*` در `.env` خالی باشد، رشته خالی برمی‌گرداند؛ کاربر فکر می‌کند صفحه خالی است.
  - عدم وجود loading state / skeleton باعث می‌شود کاربر تصور کند کلیک بی‌اثر بوده.
  - `bindSupport()` فقط بعد از render دوم صدا زده می‌شود؛ اگر render قبلی به دلیل خطای JS متوقف شود، دکمه‌ها بی‌اثر می‌مانند.
  - نبود fallback برای خطای شبکه در `api("/api/support/info")`.

## 2. فروشگاه ناقص — ویژگی‌های فروشگاهی وجود ندارد
- فقط 4 پلن هاردکد شده؛ هیچ کاتالوگ، دسته‌بندی، جستجو، فیلتر، مقایسه، تصویر محصول، ویدیو، توضیحات بلند، ویژگی‌ها، نظرات، امتیاز، موجودی، تگ، SEO وجود ندارد.
- سبد خرید ندارد: خرید مستقیم → درگاه. کاربر نمی‌تواند چند محصول را جمع کند.
- لیست علاقه‌مندی (wishlist) ندارد.
- کد تخفیف / کوپن ندارد.
- محاسبه مالیات، هزینه، تخفیف حجمی ندارد.
- فاکتور PDF ندارد؛ فقط شماره فاکتور متنی.
- تاریخچه پرداخت بدون صفحه‌بندی، جستجو، فیلتر وضعیت.
- ایمیل سفارش، رسید پرداخت، اطلاع‌رسانی ندارد (فقط OTP).
- بازگشت وجه / لغو سفارش ندارد.
- چندزبانه نیست (فقط فارسی در UI).
- ریسپانسیو ضعیف برای موبایل (tabs می‌پیچد اما منوی همبرگری ندارد).
- Accessibility: بدون aria-label کافی، بدون keyboard nav کامل.
- سئو: بدون meta description, OG, schema.org Product.
- PWA / آفلاین ندارد.
- Trust badges, نماد اعتماد, زرین‌پال لوگو, نظرات مشتریان ندارد.

## 3. پنل کاربری ناقص
- فقط لیست سفارش‌ها و کلیدها؛ تب‌های جدا برای سفارش‌ها، فاکتورها، کلیدها، تیکت‌ها، پروفایل، امنیت، اعلان‌ها وجود ندارد.
- ویرایش پروفایل (نام، رمز، 2FA) ندارد.
- بازیابی رمز عبور ندارد (فقط OTP ثبت‌نام).
- نمایش لاگ ورود، دستگاه‌های فعال ندارد.
- دانلود کلید، کپی، اشتراک‌گذاری امن ندارد.
- اعلان‌های درون‌برنامه‌ای ندارد.
- آدرس صورتحساب (حتی برای محصول دیجیتال) برای فاکتور رسمی ندارد.

## 4. پنل ادمین مخفی اما ضعیف
- آدرس مخفی فقط با هش ساده؛ بدون rate-limit جدا برای brute-force (فقط 10 تلاش، اما بدون CAPTCHA).
- بدون نشست جدا؛ فقط هدر `x-admin-token`؛ اگر توکن لو برود، کل پنل لو می‌رود.
- بدون نقش‌بندی (فقط یک ادمین).
- بدون مدیریت محصولات: قیمت‌ها از `.env` می‌آید، از پنل قابل تغییر نیست.
- بدون مدیریت کوپن‌ها.
- بدون مدیریت محتوا (FAQ, صفحات).
- بدون نمودار فروش، تحلیل، گزارش CSV/Excel.
- بدون جستجوی پیشرفته در سفارش‌ها (فقط فیلتر متنی ساده سمت کلاینت).
- بدون صفحه‌بندی سرورساید؛ `slice(-500)` خطرناک برای دیتابیس بزرگ.
- بدون بک‌آپ / ریستور.
- بدون لاگ کامل IP + UserAgent + زمان دقیق.
- `admin_audit` فقط 3000 رکورد نگه می‌دارد، بدون فیلتر.
- بدون مدیریت تنظیمات پشتیبانی (تلفن، ایمیل، تلگرام) از پنل.

## 5. امنیت و پایداری
- `Store` با نوشتن JSON ساده؛ بدون قفل فایل، بدون ترنزکشن؛ در ترافیک بالا race condition دارد.
- `DATA_DIR` بدون رمزنگاری؛ کلیدها plain-text در JSON.
- `JWT_SECRET` پیش‌فرض ضعیف اگر `.env` نباشد.
- `ADMIN_TOKEN` پیش‌فرض خالی → ادمین غیرفعال، اما هشدار فقط در کنسول.
- کپچا ساده جمع دو عدد؛ قابل دور زدن با OCR ساده؛ بدون محدودیت زمانی سخت.
- OTP: اگر SMTP/Kavenegar تنظیم نباشد، کد در پاسخ API برمی‌گردد → در پروداکشن خطرناک.
- Rate-limit حافظه‌ای (Map) → با ری‌استارت پاک می‌شود؛ در کلاستر کار نمی‌کند.
- ZarinPal: بدون اعتبارسنجی مبلغ برگشتی با دقت (فقط `Math.round`).
- بدون CSRF، بدون Helmet headers، بدون CORS محدود.
- بدون اعتبارسنجی ورودی برای `note`, `subject`, `body` (فقط slice).
- بدون محدودیت حجم تیکت‌ها برای یک کاربر (فقط 10 باز).
- بدون اسکن ویروس برای ورودی‌ها (اگر فایل پیوست اضافه شود).

## 6. تجربه کاربری (UX)
- بدون لودینگ، بدون skeleton، بدون toast برای خطاهای شبکه.
- کپی کلید با `navigator.clipboard` که در HTTP کار نمی‌کند؛ بدون fallback.
- تاریخ‌ها فقط `slice(0,10)`؛ بدون تقویم شمسی.
- قیمت‌ها: تبدیل ریال به تومان با `Math.round(rial/10)` بدون فرمت فارسی.
- بدون تایید قبل از ابطال کلید (در برخی جاها دارد، در برخی نه).
- بدون راهنمای خرید، بدون FAQ.
- لینک‌های تلگرام/ایمیل بدون `rel=noopener` در برخی جاها (در کد جدید هست اما ناقص).

## 7. کد و معماری
- `app.js` 800 خط در یک فایل؛ بدون ماژول‌بندی، بدون TypeScript، بدون تست فرانت.
- `index.js` 929 خط؛ همه چیز در یک فایل؛ بدون روتر جدا، بدون سرویس‌ها.
- `public/app.js` با `replaceAll("__ADMIN_HASH__", ADMIN_HASH)` → اگر هش شامل کاراکتر خاص باشد، JS می‌شکند (هرچند sanitize شده).
- `store.js` از `fs.writeFile` async بدون await درست؛ `_queue` فقط برای save است اما `push` بلافاصله برمی‌گردد.
- تست‌ها فقط `key-parity` و `api-support`؛ بدون تست e2e برای فروشگاه.
- مستندات فروشگاه فقط در README؛ بدون OpenAPI/Swagger.

## 8. ارتباط با دسک AURION
- دسک فقط یک لینک `Buy a key` دارد که به `store_url` می‌رود؛ اگر `store_url` خالی باشد، دکمه disabled بدون توضیح.
- بدون SSO بین فروشگاه و دسک؛ کاربر باید دوباره لاگین کند.
- بدون نمایش وضعیت لایسنس در فروشگاه.

## تغییرات لازم (خلاصه)
1. بازنویسی کامل فرانت فروشگاه به یک SPA مدرن با: سبد خرید (localStorage)، علاقه‌مندی، کوپن، مقایسه پلن‌ها، صفحه محصول، FAQ، نظرات، Trust badges، ریسپانسیو کامل، منوی موبایل، جستجو، فیلتر.
2. پنل کاربری تب‌بندی شده: داشبورد، سفارش‌ها، فاکتورها، کلیدها، تیکت‌ها، پروفایل، امنیت.
3. پنل ادمین جدا و محرمانه: لاگین با توکن + CAPTCHA، داشبورد با نمودار، مدیریت سفارش‌ها (صفحه‌بندی سرورساید)، کاربران، کلیدها، محصولات، کوپن‌ها، تیکت‌ها، تخلفات، کلیدهای مالک، لاگ ممیزی، تنظیمات پشتیبانی، بک‌آپ.
4. رفع باگ پشتیبانی: لودینگ، fallback، اطمینان از bind، تست e2e.
5. بک‌اند: افزودن collectionهای `products`, `coupons`, `settings`، endpointهای `/api/products`, `/api/coupons`, `/api/cart/checkout`, `/api/me/profile`, `/api/me/password`, `/api/admin/products`, `/api/admin/coupons`, `/api/admin/settings`, `/api/admin/export`, بهبود rate-limit, افزودن helmet headers, بهبود Store با قفل.
6. امنیت: حذف dev_code در پروداکشن، بهبود کپچا، افزودن لاگ کامل، رمزنگاری کلیدها در rest (اختیاری).
7. UX: افزودن لودر، toastهای بهتر، تاریخ شمسی، فرمت تومان فارسی، تاییدیه‌ها، راهنما.

این گزارش مبنای بازنویسی قرار می‌گیرد.
