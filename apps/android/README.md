# پوستهٔ اندروید AURION

ساخت APK روی خود گوشی، داخل ترموکس، بدون Gradle و بدون اندروید استودیو.

## این APK چه هست و چه نیست

**هست:** یک پنجرهٔ WebView که به دسک AURION در حال اجرا روی کامپیوتر شما وصل
می‌شود. همان دسک واقعی را می‌بینید — قیمت زنده، EA، ژورنال، بک‌تست — چون
دقیقاً همان صفحه است، نه یک کپی.

**نیست:** داخلش نه دسکی هست، نه موتوری، نه دیتای بازاری، و نه دمو. اگر
کامپیوتر خاموش باشد، این اپ چیزی برای نشان دادن ندارد.

چرا این‌طور طراحی شد: بک‌اند نود روی کامپیوتر هم `apps/web` را سرو می‌کند و
هم `/api` را به موتور پایتون پراکسی می‌دهد. پس وقتی گوشی مستقیم از همان
بک‌اند صفحه را می‌گیرد، تمام درخواست‌ها **same-origin** می‌شوند و فهرست مجاز
CORS سرور (که فقط loopback را نام برده) اصلاً وارد ماجرا نمی‌شود. یعنی
**هیچ تغییری در سمت سرور لازم نیست.**

## یک‌بار: آماده‌سازی ترموکس

ترموکس را از **F-Droid** نصب کنید، نه از گوگل‌پلی (نسخهٔ پلی رها شده است).

```bash
pkg update
pkg install aapt2 d8 apksigner zipalign zip openjdk-17 findutils git
```

Gradle عمداً استفاده نشده. افزونهٔ Gradle اندروید یک `aapt2` ساخته‌شده برای
`linux-x86_64` دانلود می‌کند که روی گوشی aarch64 اصلاً اجرا نمی‌شود؛ دور زدنش
شکننده‌تر از آن است که همان پنج ابزار زیرین را مستقیم صدا بزنیم.

### `android.jar`

تنها قطعه‌ای که ترموکس مطمئن بسته‌بندی نمی‌کند. فقط همین یک فایل لازم است،
نه کل SDK. هر نسخهٔ API 30 به بالا کار می‌کند.

اول ببینید از قبل دارید یا نه:

```bash
ls $PREFIX/share/java/android.jar
ls $ANDROID_HOME/platforms/android-*/android.jar
```

اگر نبود، یکی تهیه کنید و مسیرش را بدهید:

```bash
export ANDROID_JAR=/مسیر/به/android.jar
```

## ساخت

```bash
cd apps/android
./build.sh
```

خروجی: `apps/android/build/AURION.apk`. اگر دسترسی حافظه را داده باشید
(`termux-setup-storage`)، یک کپی هم در پوشهٔ Download گذاشته می‌شود تا با
فایل‌منیجر قابل نصب باشد.

اسکریپت در اولین اجرا یک کلید امضای موقت (`debug.keystore`) می‌سازد.
**نگهش دارید** — اندروید آپدیتی را که با کلید دیگری امضا شده باشد نصب
نمی‌کند. برای کلید خودتان:

```bash
export AURION_KEYSTORE=~/my.keystore
export AURION_KEYSTORE_PASS=...
export AURION_KEY_ALIAS=...
```

کلید و پوشهٔ `build/` هر دو در `.gitignore` هستند.

## سمت کامپیوتر

۱. دسک را اجرا کنید (`npm start`). بک‌اند پیش‌فرض روی `0.0.0.0:8080` گوش
   می‌دهد، پس از شبکه در دسترس است و نیازی به تغییر ندارد.
۲. آدرس کامپیوتر را پیدا کنید: `ipconfig` روی ویندوز — چیزی مثل
   `192.168.1.20`.
۳. فایروال ویندوز باید پورت ۸۰۸۰ را روی شبکهٔ **Private** اجازه دهد. این
   معمول‌ترین دلیل کار نکردن است.
۴. گوشی و کامپیوتر باید روی یک شبکه باشند. هات‌اسپات خود گوشی هم کار
   می‌کند.

در اپ فقط `192.168.1.20` را بنویسید؛ اگر پورت ننویسید ۸۰۸۰ فرض می‌شود.

## نکته‌های رفتاری

- **آدرس عوض کردن:** دکمهٔ بازگشت را در صفحهٔ اول دسک بزنید؛ پنجره‌ای با
  گزینهٔ «تغییر آدرس» باز می‌شود.
- **لینک‌های بیرونی** (تلگرام، فروشگاه) در مرورگر واقعی باز می‌شوند، نه
  داخل پنجره‌ای که نوار آدرس ندارد.
- **صفحه روشن می‌ماند** تا موقع رصد پوزیشن خاموش نشود.
- **Service worker کار نمی‌کند** و این درست است: روی یک IP شبکه مرورگر
  «کانتکست امن» ندارد. ثبتش در `app.js` با `"serviceWorker" in navigator`
  و یک `.catch()` محافظت شده، پس چیزی نمی‌شکند — فقط کش آفلاین ندارید.
- **`usesCleartextTraffic` روشن است،** چون روی شبکهٔ محلی گواهی‌ای برای
  اعتبارسنجی وجود ندارد. این اپ را به هیچ آدرسی روی اینترنت عمومی وصل
  نکنید.

## عیب‌یابی

| نشانه | علت محتمل |
|---|---|
| `android.jar not found` | `ANDROID_JAR` را ست کنید |
| `aapt2` خطای sdk 35 | `TARGET_SDK` در `build.sh` را ۳۴ نگه دارید |
| نصب رد می‌شود روی اندروید ۱۱+ | `pkg install zipalign` و دوباره بسازید |
| `ERR_CONNECTION_REFUSED` | دسک اجرا نیست، یا فایروال پورت ۸۰۸۰ را بسته |
| `ERR_ADDRESS_UNREACHABLE` | گوشی و کامپیوتر روی یک شبکه نیستند |
| اپ نصب می‌شود ولی موقع باز شدن می‌بندد | `d8` بدون `--lib` اجرا شده؛ اسکریپت این را می‌دهد، دستی نسازید |
